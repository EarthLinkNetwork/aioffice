# アプリの一覧が読めない時に 0 件にしない（build 7）の範囲

## 保証すること
- 通知 API の会社の一覧（GET /bindings）・件の一覧（GET /cards）が 200 でない時、アプリは空の一覧にせず失敗として扱う。受信箱・会社・バッジは前に読めた状態を残し、知らせに「読み直せませんでした」を出す。
- 一覧を読み直すすべての経路（起動・会社の読み直し・前面に戻った時・承認や判断の後・見たにした後・会社とつないだ後・引いて読み直し）で、失敗を黙って捨てず知らせを出す。未処理の例外にしない。
- 見たにした件・外した会社は、読み直しが失敗しても手元の一覧から外す。
- 設定の画面は、通知の設定と会社の一覧のうち読めた方だけを出し、読めなかった時は知らせを出す。
- 通知の設定（GET /prefs）が 200 でない時は既定値を作らず失敗にする（切り替えで設定を誤った値に上書きしない）。

## 保証しないこと
- 通知 API の 500 そのものの原因（Amplify の実行環境・記録が残らない設定）。
- 起動して最初の読み込みが失敗した時に、前の一覧を出すこと（前の一覧が無いので空のまま、知らせだけ出る）。

## 前提
- 2026-11-13 06:48〜06:51（UTC）に通知 API の dev が GET /bindings に 500（CloudFront の OriginError）を返し、アプリが会社 0 件・件 0 件と表示した（アクセスの記録で確かめた）。

## 受け入れる限界
- 一時的な 500 の間は、受信箱の中身が古いままになる。引いて読み直せば戻る。
